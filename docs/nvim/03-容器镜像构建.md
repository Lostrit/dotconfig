# 容器镜像构建与持久化

本文档整理了在当前运行中的容器里**无法直接完成**、需要写进 Dockerfile 或容器编排配置的部分。

目标：插件、语法解析器、LSP 等工具全部在**构建镜像时**下载并锁定版本；容器运行时不联网也能完整使用。

## 一、哪些东西放在哪里

| 路径 | 内容 | 来源 | 建议 |
| --- | --- | --- | --- |
| `~/.config/nvim` → `/workspace/nvim` | 本配置仓库（git 管理） | 持久化卷 | 已经是持久化卷 ✅ |
| `~/.local/share/nvim/lazy/` | 插件源码（按 `lazy-lock.json` 锁定） | **镜像构建时写入** | 放在镜像内，**不要**挂载卷（会遮住镜像里预装的内容） |
| `~/.local/share/nvim/site/parser/` | treesitter 语法解析器（编译好的 `.so`） | **镜像构建时写入** | 同上 |
| `~/.local/share/nvim/mason/` | LSP、prettier、hadolint 等工具 | **镜像构建时写入** | 同上 |
| `~/.local/state/nvim/` | 撤销历史、会话、光标位置记录（shada）、日志 | 运行时产生 | **建议挂载持久化卷**，重建容器后仍能撤销、恢复会话 |
| `~/.cache/nvim/` | 缓存 | 运行时产生 | 可以丢弃 |

## 二、版本是怎么锁定的

| 对象 | 锁定依据 | 安装方式 |
| --- | --- | --- |
| lazy.nvim 与全部插件（包括 LazyVim 本身） | `lazy-lock.json` 里记录的 git 提交 | `:Lazy restore` |
| treesitter 语法解析器 | 由锁定版本的 nvim-treesitter 决定，它内部记录了每个解析器的版本 | nvim-treesitter 的 `install()` |
| Mason 工具 | `lua/config/mason-tools.lua` 里的版本号 | `:MasonInstall 名字@版本` |
| blink.cmp 模糊匹配库 | blink.cmp 锁定的 git 标签对应的预编译文件 | blink.cmp 的下载器 |
| nvim、tree-sitter CLI、node | 你的 `~/.config/mise/config.toml` | mise |

以上步骤全部由 `scripts/bootstrap.sh` 完成，每一步结束后都会校验，任何一项失败都会以非零状态码退出，让镜像构建失败，而不是生成一个缺东西的镜像。

## 三、Dockerfile 片段

在现有 Dockerfile 里、**mise 工具安装完成之后**加入以下内容：

```dockerfile
# ---- 系统依赖 ----------------------------------------------------------
# unzip：Mason 解压部分工具需要（例如以后想加回 stylua）
# （git、gcc、make、curl、tar、gzip 当前镜像已有；tree-sitter CLI 由 mise 提供）
USER root
RUN apt-get update \
 && apt-get install -y --no-install-recommends unzip \
 && rm -rf /var/lib/apt/lists/*

# ---- nvim 配置与预装 ---------------------------------------------------
USER miniview
# 构建时把配置复制到镜像里，供 bootstrap 使用。
# 运行时 ~/.config/nvim 仍然是指向 /workspace/nvim（持久化卷）的软链接，
# 两者的 lazy-lock.json 与 mason-tools.lua 应保持一致（见第五节“升级流程”）。
COPY --chown=miniview:miniview nvim /home/miniview/.config/nvim

# mise exec 保证 nvim / node / tree-sitter 在 PATH 中
RUN mise exec -- bash /home/miniview/.config/nvim/scripts/bootstrap.sh

# 复制进来的配置只用于构建，运行时换成指向持久化卷的软链接
RUN rm -rf /home/miniview/.config/nvim \
 && ln -s /workspace/nvim /home/miniview/.config/nvim
```

> `COPY nvim ...` 的源路径 `nvim` 指构建上下文里的本配置仓库目录，请按实际存放位置调整。

**构建时的网络说明**：

- 插件通过 `git clone` 下载，**会受到 `~/.config/git/config` 里 `url.*.insteadOf` 规则的影响**。你现在的 git 配置把 GitHub 地址改写到镜像站 `github.cnxiaobai.com`，调试期间这个镜像站返回过 403，导致 lazy.nvim 下载失败。镜像站不稳定时，可以只对 bootstrap 这一步临时忽略全局 git 配置：
  ```dockerfile
  RUN GIT_CONFIG_GLOBAL=/dev/null mise exec -- bash /home/miniview/.config/nvim/scripts/bootstrap.sh
  ```
- 语法解析器、Mason 工具、blink.cmp 库通过 curl 或 npm 下载，会使用 `https_proxy` 等代理环境变量。
- 调试期间多次遇到网络偶发失败（GitHub 连接 TLS 握手中断、Releases 下载失败）。脚本的每一步都会校验结果（插件是否位于锁定的提交、解析器是否齐全、工具版本是否一致），不齐时只重装缺少的部分，最多重试 3 次，仍失败才让构建失败。
- 整个过程约需 2～5 分钟，大部分时间花在编译语法解析器和 npm 安装上。

## 四、建议的持久化卷

```yaml
# docker compose 示例（只列出与 nvim 相关的部分）
services:
  dev:
    volumes:
      - ./workspace:/workspace                   # 已有：包含 /workspace/nvim 配置
      - nvim-state:/home/miniview/.local/state/nvim   # 新增：撤销历史、会话等
volumes:
  nvim-state:
```

挂载 `~/.local/state/nvim` 的效果：

- **撤销历史**：LazyVim 默认开启持久撤销（`undofile`）。重建容器后打开文件，仍然可以用 `u` 撤销之前的修改
- **会话**：`空格 q s` 恢复上次打开的文件和窗口布局
- **光标位置、搜索历史、命令历史**：保存在 shada 文件里

## 五、升级流程

版本锁定之后，插件和工具**不会自动升级**。想升级时：

1. **插件**：在 nvim 里运行 `:Lazy update`，试用确认没问题后，`lazy-lock.json` 会被更新。
2. **Mason 工具**：`:Mason` 界面会显示可升级的版本。把新版本号写进 `lua/config/mason-tools.lua`。
3. **验证**：在配置目录里运行 `bash scripts/bootstrap.sh`，确认能从头安装成功。
4. **提交**：`git commit` 提交 `lazy-lock.json` 和 `mason-tools.lua`。
5. **重建镜像**。

如果只改了配置、没有重建镜像，也能继续工作：下次启动 `nvim` 时，缺少的插件会按 `lazy-lock.json` 自动安装；Mason 工具如果与 `mason-tools.lua` 中的版本不一致，会自动改装为清单中的版本（需要联网）。安装结果与重建镜像相同，只是容器重建后需要重新下载。

## 六、Ghostty + ssh + tmux 相关

### 1. terminfo

Ghostty 通过 ssh 连接时会把 `TERM` 设为 `xterm-ghostty`。当前镜像已经包含 `/usr/share/terminfo/x/xterm-ghostty` ✅。以后重建镜像时，如果这个文件丢失，tmux 会报 `missing or unsuitable terminal: xterm-ghostty`。有两种修复方式：

- 在镜像中保留这个 terminfo 文件（推荐，就是目前的做法）；或者
- 在本机 Ghostty 配置中加入 `shell-integration-features = ssh-terminfo`，由 Ghostty 在 ssh 时自动把 terminfo 安装到远端。

### 2. tmux 设置

已检查你当前的 tmux 会话：

| 项目 | 状态 | 说明 |
| --- | --- | --- |
| `escape-time` | 10ms ✅ | tmux 3.6 的默认值，按 `Esc` 没有延迟 |
| 真彩色（RGB） | ✅ | Ghostty 会主动告知 tmux 支持真彩色，主题颜色可以正确显示 |
| 剪贴板（OSC 52） | ✅ | 你的配置里已有 `set -s set-clipboard on` 和 `terminal-features ',*:clipboard'` |
| `focus-events` | on ✅ | 已在 `~/.config/tmux/tmux.conf` 中开启：你在别处（如 lazygit、终端里的 git checkout）改了文件，切回 nvim 时会自动刷新 |

tmux.conf 中已加入的设置：

```tmux
set -g focus-events on
```

### 3. 默认编辑器（可选，未修改）

`~/.config/mise/config.toml` 中目前是 `EDITOR = "micro"`、`VISUAL = "micro"`，git 提交信息、`crontab -e` 等场景会打开 micro。熟悉 nvim 以后，如果想统一用 nvim，可以改为：

```toml
EDITOR = "nvim"
VISUAL = "nvim"
```

对新手来说，micro（操作方式类似普通编辑器）作为临时编辑器更友好，因此建议暂时保持不变。
