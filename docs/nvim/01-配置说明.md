# 配置说明

这份文档写给第一次接触 Neovim 的人，逐个解释本配置里每个文件改了什么、为什么改、改完之后会看到什么效果。

## 一、先弄清楚几个概念

| 名词 | 是什么 |
| --- | --- |
| **Neovim（nvim）** | 在终端里运行的文本编辑器，本身只提供最基础的编辑功能 |
| **LazyVim** | 一套现成的 Neovim 配置发行版，预先配好了文件树、搜索、补全、Git 等常用功能。本仓库就是在 LazyVim 官方 starter 模板上做的定制 |
| **lazy.nvim** | LazyVim 用的插件管理器，负责下载、加载插件，并把插件版本记录在 `lazy-lock.json` |
| **插件** | 给 Neovim 扩展功能的 Lua 代码，例如文件树、模糊搜索 |
| **LSP（语言服务器）** | 独立运行的程序，提供"跳转到定义、自动补全、报错提示、重命名"等语言相关的智能功能。每种语言各有自己的语言服务器，例如 TypeScript 用 vtsls |
| **Mason** | 在 Neovim 内部管理 LSP、格式化工具和检查工具的安装器 |
| **Treesitter** | 语法解析器，负责准确的语法高亮和按语法结构选择代码。每种语言需要编译一个解析器 |
| **Extras** | LazyVim 官方打包好的可选功能。例如 `lang.typescript` 会一次性配好 TS 所需的 LSP、解析器、格式化工具和快捷键 |

## 二、目录结构

```
~/.config/nvim  →  /workspace/nvim   （软链接，位于持久化卷上）
├── init.lua                   入口文件，只做一件事：加载 lua/config/lazy.lua
├── lazyvim.json               启用了哪些 LazyVim Extras（可在 nvim 里用 :LazyExtras 修改）
├── lazy-lock.json             每个插件锁定到的 git 提交（版本锁）
├── stylua.toml                Lua 代码的格式规则（给本配置自身用）
├── lua/
│   ├── config/                LazyVim 约定的配置入口，会被自动加载
│   │   ├── lazy.lua           插件管理器的设置
│   │   ├── options.lua        编辑器选项（剪贴板、文件类型、系统打开方式、关闭远程插件支持）
│   │   ├── keymaps.lua        自定义快捷键（目前为空，沿用 LazyVim 默认）
│   │   ├── autocmds.lua       自动命令（目前为空）
│   │   ├── mason-tools.lua    Mason 工具清单与固定版本
│   │   └── zh.lua             which-key 中文翻译表
│   └── plugins/               插件配置，这里每个文件都会被自动加载
│       ├── colorscheme.lua    配色主题
│       ├── mason.lua          告诉 Mason 需要安装哪些工具
│       ├── formatting.lua     去掉本环境用不到的格式化工具
│       ├── which-key-zh.lua   让 which-key 使用中文翻译表
│       ├── dashboard-zh.lua   启动页菜单及其按键说明的中文化
│       └── bootstrap.lua      只在镜像构建时生效，平时不起作用
├── scripts/
│   ├── bootstrap.sh           镜像构建时运行的离线预装脚本
│   └── bootstrap.lua          上面脚本调用的具体安装逻辑
└── docs/                      本文档
```

**LazyVim 的加载顺序**：`init.lua` → `lua/config/lazy.lua` 启动插件管理器 → 加载 LazyVim 本体和 `lazyvim.json` 里启用的 Extras → 加载 `lua/plugins/` 下的所有文件（覆盖或补充前面的设置）→ 加载 `options.lua` / `keymaps.lua` / `autocmds.lua`。

## 三、逐项说明改动

### 1. `lazyvim.json`：启用语言支持（Extras）

| Extra | 支持的文件或技术 | 内容 |
| --- | --- | --- |
| `lang.typescript` | `.js` `.jsx` `.ts` `.tsx`，node / bun / react | vtsls 语言服务器：补全、跳转、类型检查、自动 import |
| `lang.vue` | `.vue` | vue-language-server，与 vtsls 协同处理 `<script>` 部分 |
| `lang.json` | `.json` `.jsonc` | jsonls + SchemaStore：`package.json`、`tsconfig.json` 等常见文件的字段补全和校验 |
| `lang.yaml` | `.yaml` `.yml` | yamlls + SchemaStore：GitHub Actions、k8s 等常见 YAML 的补全和校验 |
| `lang.toml` | `.toml` | taplo：TOML 的补全、校验和格式化 |
| `lang.docker` | `Dockerfile`、compose 文件 | dockerls、docker-compose 语言服务、hadolint（Dockerfile 最佳实践检查） |
| `linting.eslint` | JS / TS / Vue | 项目里有 ESLint 配置时，直接在编辑器内显示 ESLint 问题 |
| `formatting.prettier` | JS / TS / Vue / JSON / YAML / CSS / Markdown | 保存时用 Prettier 自动格式化 |

**效果**：打开这些文件时，语言服务器会自动启动。输入代码时有补全，出错时行尾显示提示，保存时自动格式化。

> **关于 bun**：bun 没有专门的语言服务器。TS/JS 代码统一由 vtsls 处理，项目里装上 `@types/bun` 后，`Bun.*` API 也能补全。

> **关于 Prettier 和 ESLint**：两者都会优先使用项目 `node_modules` 里的版本和项目自己的配置，找不到时才用 Mason 装的版本。

### 2. `lua/config/lazy.lua`：插件管理器

- **关闭后台更新检查**（`checker.enabled = false`）。LazyVim 默认会定期联网检查插件更新。本配置的插件版本由 `lazy-lock.json` 锁定、在镜像里预装，不需要这个检查。升级流程见 `03-容器镜像构建.md`。
- **首次安装时的临时主题**改为 catppuccin-mocha。
- **首次启动时按锁定版本预先下载 lazy.nvim 和 LazyVim**。starter 原本只下载 lazy.nvim，而且下载的是 stable 分支的最新版。这样有两个问题：
  1. lazy.nvim 自身不是锁定的版本。
  2. **更严重的问题**：LazyVim 带来了大部分插件的清单。LazyVim 还没下载时，lazy.nvim 只认识本配置直接写出的 8 个插件。它装完这 8 个后，会按"当前已知的插件"重写 `lazy-lock.json`，把其余 25 个插件的锁定记录删掉，结果这些插件被装成最新版。实测中 3 个插件因此偏离了锁定版本。

  现在的做法是先读取 `lazy-lock.json`，把 lazy.nvim 和 LazyVim 都克隆并切换到锁定的提交，再启动 lazy.nvim。这样它一开始就能看到全部插件，一次性全部按锁文件安装，锁文件也不会被改写。
- **下载失败时的处理**：删除下载了一半的目录，下次启动时重新下载；在没有界面的 headless 模式（如镜像构建）下直接退出，不再等待按键。
- **关闭 luarocks 支持**（`rocks.enabled = false`）。有极少数插件以 Lua 包管理器 luarocks 的形式发布，lazy.nvim 默认为此做准备，并在 `:checkhealth` 中报告缺少 luarocks（1 个 ERROR、3 个 WARNING）。本配置没有这类插件，关掉即可。
- **保留 `:Tutor`**。starter 默认禁用了 nvim 自带的交互式教程，这里重新启用，方便新手学习。

### 3. `lua/config/options.lua`：编辑器选项

**剪贴板（OSC 52）**

你的使用链路是 Ghostty（本机）→ ssh → tmux → nvim。nvim 运行在容器里，没法直接访问本机剪贴板。OSC 52 是一种终端协议，nvim 把要复制的文字编码后发给终端，经过 tmux 转发，最终由 Ghostty 写入本机剪贴板。

这项设置**按环境自动判断**：通过 ssh 连接，或者系统里没有剪贴板工具（如本容器）时，使用 OSC 52；在有桌面的 Linux 上本地运行（有 `wl-copy` / `xclip` / `xsel`）时，沿用 nvim 自动检测到的系统剪贴板，复制和粘贴都直接走系统剪贴板。

- **效果**：在 nvim 里用 `y` 复制（或用 `d` 删除）的内容，可以直接在本机的浏览器、聊天软件里粘贴。
- **粘贴**：`p` 只粘贴 nvim 自己记住的内容，不读取本机剪贴板。读取剪贴板时 Ghostty 每次都会弹窗确认，体验很差。要把本机剪贴板的内容贴进 nvim，请先按 `i` 进入插入模式，再用 Ghostty 的粘贴快捷键（macOS 为 `Cmd+V`，Linux 为 `Ctrl+Shift+V`）。

**文件类型识别**

- `bun.lock` 识别为 JSONC（带注释的 JSON），能正确高亮，不会满屏报错。
- `compose.yaml`、`docker-compose*.yml` 识别为 docker-compose 文件，会同时启用 docker-compose 语言服务（检查服务名、镜像等字段）和 YAML 语言服务。

**关闭远程插件支持（Node / Perl / Python / Ruby provider）**

nvim 支持用这些语言编写的旧式"远程插件"，每种语言对应一个 provider，启动时会去寻找相应的运行环境。本配置里没有这类插件，所以全部关闭。

- **效果**：启动略快；`:checkhealth` 不再出现"缺少 neovim npm 包 / Python 模块 / Perl 模块 / Ruby"等 7 条警告。
- **不影响**：node、bun 开发本身，以及语言服务器（它们是独立程序，和 provider 无关）。

**"用系统程序打开"改为复制链接**

`gx`（打开光标处的链接）、`空格 g B`（在浏览器中打开 Git 远程仓库）等功能，原本会调用系统程序打开链接。nvim 运行在容器里，既没有浏览器，也无法调用你本机的程序，所以这些功能原本会直接报错。

- **现在的效果**：把链接复制到本机剪贴板，并在右上角提示"已复制到剪贴板"，再到本机浏览器里粘贴即可。
- 同样**按环境自动判断**：只在通过 ssh 连接，或者系统里没有 `xdg-open` 这类"打开"程序时才这样处理；在桌面 Linux 本地运行时，保持 nvim 默认行为，直接用浏览器打开。
- `:checkhealth` 中的 `vim.ui.open: no handler found` 警告仍会出现：检查的是容器里有没有 `xdg-open` 这类程序，而不是看功能是否可用。这条可以忽略。

### 4. `lua/plugins/colorscheme.lua`：配色主题

把主题设为 **Catppuccin Mocha**，与你的 tmux、fzf、bat 等工具统一配色。LazyVim 本来就自带这个主题，不额外下载东西。可以用 `空格 u C` 临时预览其他主题。

另外关闭了 catppuccin 的"自动检测已安装插件"（`auto_integrations`）。这项检测会调用 nvim 0.12 自带的插件管理器 `vim.pack`，而后者会顺带创建一个空目录 `~/.local/share/nvim/site/pack/core`，导致 `:checkhealth` 出现两条误报（lazy.nvim 的 "found existing packages" 和 vim.pack 的 "Lockfile is absent"）。LazyVim 已经显式列出了各插件的配色集成，自动检测只多补了补全菜单 blink.cmp 这一项，现在改为手动写上，配色效果不变。

### 5. `lua/config/mason-tools.lua` 与 `lua/plugins/mason.lua`：工具清单

`mason-tools.lua` 是**唯一**记录 Mason 工具和版本号的地方：

- `lua/plugins/mason.lua`：平时启动 nvim 时，在后台按其中的**版本号**安装缺少的工具。已安装的版本与清单不一致时，会改装为清单中的版本
- `scripts/bootstrap.lua`：镜像构建时按同样的版本同步安装，并逐项校验

LazyVim 原本的做法是：启动时发现缺少哪个工具，就安装它的**最新版**；语言服务器还会被另一个插件 mason-lspconfig 再按最新版安装一遍。`mason.lua` 把这两条"安装最新版"的路径都关掉了：

- 清空 LazyVim 的安装清单，改为按固定版本安装
- 对清单里已有的语言服务器设置 `mason = false`，不再交给 mason-lspconfig 安装，而是直接启用。Mason 会把装好的程序加入 `PATH`，所以语言服务器照样能找到

因此在新环境里直接运行 `nvim`，得到的工具版本与构建脚本完全相同。

LazyVim 默认还会安装 stylua（Lua 代码格式化工具），本配置把它去掉了：stylua 以 zip 发布，需要系统里有 `unzip`；它只在编辑本 nvim 配置时有用，缺了它时 Lua 文件会改用 lua-language-server 自带的格式化。

可以在 nvim 里运行 `:Mason` 查看所有工具的安装状态。

**`lua/plugins/formatting.lua`**：LazyVim 默认为 Lua 文件配置了 stylua，为 fish shell 文件配置了 fish_indent，这两个工具本环境都没有，`:checkhealth` 会报告找不到。这里把它们从格式化配置中去掉。Lua 文件保存时会自动改用 lua-language-server 格式化（已验证可用）。

### 6. `lua/config/zh.lua`、`which-key-zh.lua`、`dashboard-zh.lua`：中文提示

**which-key** 是按下空格等前缀键后，屏幕右下角弹出的快捷键提示面板，是新手探索快捷键的主要方式。

- `zh.lua` 是英中对照表，共覆盖 573 条按键说明：
  - LazyVim 和已启用 Extras 的全部快捷键，包括 LSP 快捷键、文本对象、寄存器面板和标记面板
  - 文件树、搜索窗口里的按键（原文是 `explorer_add`、`toggle_hidden` 这样的动作名）
  - Lazy 插件管理界面（`:Lazy`）里的按键

  开关类按键会显示为"启用 xxx / 禁用 xxx"。
- `which-key-zh.lua` 在 which-key 显示说明之前先查这张表，查到就换成中文；另外把面板底部的"close / back / scroll"换成"关闭 / 返回上级 / 滚动"。
- `dashboard-zh.lua` 处理启动页（直接运行 `nvim` 时看到的首页）：
  - 把启动页的菜单文字翻译成中文。
  - 启动页插件（snacks）给每个菜单按键注册快捷键时，说明一律写死为 "Dashboard action"，所以在启动页上按空格再按 Backspace 回到最上级时，会看到一排相同的 "Dashboard action"。翻译表是按原文逐条查的，没法区分它们，因此在启动页每次显示完成后，把这些按键的说明改成对应菜单项的中文名称（例如 `f ➜ 查找文件`、`r ➜ 最近打开的文件`）。
- 分组前的 `+` 号表示"这是一个子菜单，还能继续按键"。
- 搜索窗口里按 `?` 显示的帮助列表是 snacks 插件自己画的，不经过 which-key，仍为英文。

**以后添加新插件或快捷键时**，如果看到英文说明，把英文原文作为键、中文作为值加进 `zh.lua` 的 `M.exact` 表即可（原文开头的 `+`、`:` 要去掉）。

### 7. `lua/plugins/bootstrap.lua`：构建专用

只有设置了环境变量 `NVIM_BOOTSTRAP=1`（`scripts/bootstrap.sh` 会自动设置）时才生效，平时是空文件。构建脚本需要**同步**安装并逐项校验，所以要关掉启动时的**后台**自动安装（语法解析器由本文件处理，Mason 工具由 `mason.lua` 处理），避免两者同时安装、互相冲突。

**两种安装方式的关系**：

| | 直接运行 `nvim` | `scripts/bootstrap.sh` |
| --- | --- | --- |
| 插件 | 按 `lazy-lock.json` | 按 `lazy-lock.json` |
| Mason 工具 | 按 `mason-tools.lua`，后台安装 | 按 `mason-tools.lua`，同步安装并校验 |
| 语法解析器 | 后台编译 | 同步编译并校验 |
| 补全模糊匹配库 | 首次进入插入模式时下载 | 立即下载，失败自动重试 |
| 适用场景 | 任何装好了前提程序的 Linux | 镜像构建、需要离线使用的环境 |

两者的安装结果完全相同，都已从空目录开始实测验证。

### 8. 删除了 `lua/plugins/example.lua`

这是 starter 自带的示例文件，第一行就 `return {}` 了，并不生效。删掉它，避免让人误以为里面的配置在起作用。

## 五、`:LazyHealth` / `:checkhealth` 体检结果说明

`:LazyHealth` 会先加载全部插件，再运行 `:checkhealth`，检查每个插件的**所有可选功能**是否具备运行条件。因此即使一切正常，也会有不少 WARNING 和 ERROR：它们大多只是说明"某个可选功能用不了"，而不是"配置坏了"。

### 已消除的警告

| 原警告 | 原因 | 处理 |
| --- | --- | --- |
| luarocks / hererocks 未安装（1 个 ERROR、3 个 WARNING） | lazy.nvim 默认支持 luarocks 插件 | `lazy.lua` 中关闭 |
| Node / Perl / Python / Ruby provider 缺失（7 条） | 远程插件支持，本配置用不到 | `options.lua` 中关闭 |
| conform：stylua、fish_indent 找不到 | LazyVim 为 Lua 和 fish 预设的格式化工具 | `formatting.lua` 中去掉 |
| lazy.nvim：found existing packages at `site/pack/core` | catppuccin 调用 `vim.pack` 创建的空目录 | 关闭 catppuccin 自动检测，并删除空目录 |
| vim.pack：Lockfile is absent | 同上 | 同上 |

### 有破坏性影响、需要留意的

只有一项：

- **Snacks.explorer：ERROR `None of the tools found: 'trash', 'gio' …`**
  **含义**：容器里没有"回收站"工具，所以**在文件树里删除的文件会被直接删除，无法恢复**。删除前会弹出确认，按 `y` 之前请看清楚。
  **可选的解决办法**：安装 `trash` 命令后，文件树删除的文件会移进回收站 `~/.local/share/Trash`，这条 ERROR 也会消失。最方便的是用 mise 安装 Node.js 版的 trash-cli：在 `~/.config/mise/config.toml` 中加入
  ```toml
  [tools."npm:trash-cli"]
  version = "7.2.0"   # 2026-09 时的最新版，可用 mise ls-remote npm:trash-cli 查看
  ```
  需要注意：`~/.local/share` 不在持久化卷上，重建容器后回收站会被清空。另外，已经提交到 Git 的代码即使删错了，也可以用 `git checkout -- 文件` 找回，所以不安装也可以。

### 无法消除、也不需要处理的

**补全（blink.cmp）**
- `Some providers may show up as "disabled" but are enabled dynamically`：提示性信息。命令行补全等来源只在需要时才启用，体检时看起来是"禁用"。

**格式化（conform）**
- `prettier unavailable: Condition failed`：体检是在 `checkhealth` 这个特殊窗口里运行的，Prettier 只对 JS/TS/Vue/JSON/YAML 等文件生效，在这里当然"条件不满足"。打开真正的代码文件时它是正常工作的（见第四节）。

**搜索替换（grug-far）**
- `ast-grep: not found`：`空格 s r` 搜索替换默认用 ripgrep（已安装），ast-grep 是一种"按语法结构搜索"的可选引擎，新手用不到。以后想用，可以在 mise 中加 `aqua:ast-grep/ast-grep`。

**Mason**
- `unzip: not available`：部分工具以 zip 发布，需要它来解压。当前清单里的工具都不需要，但建议在镜像中安装（`03-容器镜像构建.md` 的 Dockerfile 片段已包含），方便以后添加工具。
- `wget: not available`：Mason 会优先用 curl 下载，curl 已安装。
- `Go / cargo / luarocks / Ruby / RubyGem / Composer / PHP / javac / java / julia / python / pip / python venv: not available`：Mason 能安装用这些语言编写的工具，检查的是"安装它们的条件"。本配置的工具只用到 npm（node）和直接下载的二进制文件，这些语言都不需要。

**Snacks.image（在终端里显示图片、PDF、公式、流程图）**
- `setup {disabled}`：这个功能本身没有启用。
- `kitty / wezterm / ghostty 都找不到`、`your terminal does not support the kitty graphics protocol`：它检查的是**容器里**有没有这些终端程序，以及当前终端能否显示图片。你的 Ghostty 在本机，中间还隔着 ssh 和 tmux，这个检查必然失败。
- `magick`、`gs`、`tectonic / pdflatex`、`mmdc` 找不到，以及 `Missing Treesitter languages`：分别是转换图片、渲染 PDF、LaTeX 公式、Mermaid 流程图所需的工具和语法解析器，都是图片功能的附属功能。

**搜索窗口（Snacks.picker）**
- `SQLite3 is not available`：搜索窗口会记住你常打开的文件，把它们排在前面。有 SQLite 时存进数据库，没有时存进普通文件，功能一样。

**Snacks.statuscolumn**
- `setup {disabled}`：LazyVim 使用自己的行号栏实现，没有启用 snacks 的这一个。

**tmux**
- `True color support could not be detected`：nvim 通过 `tmux show-messages -T` 查看**当前连接到 tmux 的终端**是否支持真彩色。我在测试时用的是后台 tmux，没有连接真实终端，所以会出现这条。你从 Ghostty 连入时，之前已确认 tmux 为你的终端开启了 RGB（真彩色）。如果你**在自己的会话里**运行体检仍看到这条，可以在 `~/.config/tmux/tmux.conf` 中加一行 `set -as terminal-features ',xterm-ghostty:RGB'`。
- 判断方法：在 nvim 里执行 `:lua print(vim.o.termguicolors)` 显示 `true`，并且主题颜色看起来柔和、没有色块断层，就说明真彩色正常。

**外部工具**
- `vim.ui.open: no handler found`：容器里没有 `xdg-open` 等"用系统程序打开"的工具。本配置已改为复制链接（见第三节第 3 条），这条检查仍会出现，可以忽略。

**LSP（vim.lsp）**
- `Unknown filetype 'javascript.jsx' / 'typescript.tsx' / 'yaml.gitlab' / 'yaml.helm-values'`：语言服务器的官方默认配置里，列了一些老版本 nvim 用过的文件类型名称（例如现在的 TSX 文件类型叫 `typescriptreact`，以前叫 `typescript.tsx`），或者本配置没有启用的类型（GitLab CI、Helm）。nvim 0.12 不认识这些名称，所以提示一下。不影响真正的文件类型，各语言服务都已验证正常工作。

**which-key**
- `In mode n, <g> overlaps with <gx>, <gr>…` 等"按键重叠"：`g` 本身是一个按键，同时又是 `gx`、`gr` 等组合键的前缀。按下 `g` 后 nvim 会稍等一下，看你是否还要继续按键，这正是 which-key 弹出提示的时机。这是 vim 的设计本身，which-key 自己也在体检结果里说明了："WARNINGS … don't necessarily indicate a problem"。`i` / `a`（文本对象的"内部 / 外围"）同理。
